# SignalOps 中文学习指南

这份指南的目标不是让你背诵代码，而是确保你能够独立解释、运行和修改项目。

## 一、项目解决什么问题

真实云平台会持续产生大量日志。运维人员不可能逐条阅读，因此需要程序自动完成：

1. 读取和校验日志；
2. 按服务统计错误率和延迟；
3. 与正常基线进行比较；
4. 识别异常状态；
5. 将相关异常合并成事件；
6. 给出可执行的排查步骤。

SignalOps 实现了这条最小但完整的 AIOps 工作链路。

## 二、需要理解的核心文件

### `signalops/parser.py`

负责读取 JSONL 日志，每一行都是一个 JSON 对象。它会检查时间、服务名、日志级别、状态码和延迟格式。输入错误时直接指出具体行号。

你需要理解：为什么数据校验必须发生在统计和异常检测之前。

### `signalops/metrics.py`

按服务计算日志总量、错误数量、错误率、平均延迟和 P95 延迟。

P95 延迟表示 95% 的请求延迟不超过该值。相比平均值，它更容易暴露少量但严重的慢请求。

### `signalops/detector.py`

将当前时间窗口与基线进行比较，识别四类信号：

- 错误率突增；
- P95 延迟升高；
- 同一错误码反复出现；
- 日志或请求量异常下降。

这些规则是透明的。你可以直接指出阈值在哪里，以及为什么触发。

### `signalops/incidents.py`

同一服务可能同时出现多个信号。例如错误率升高、延迟升高和超时错误重复出现。这个模块将它们合并成一个事件，避免产生大量重复告警。

### `signalops/runbooks.py`

根据异常类型给出排查建议，例如检查错误模式、Trace ID、近期发布和上游依赖。它不是自动修复，而是把分析结果转化为下一步行动。

### `signalops/pipeline.py`

连接全部模块，并输出 `public/data/report.json`。网站展示的数据正是这个文件，而不是手工填写的数字。

## 三、亲自运行

```bash
python3 scripts/generate_sample_logs.py
python3 -m signalops analyze --input data/sample_logs.jsonl --baseline data/baseline_logs.jsonl --output public/data/report.json
python3 -m pytest
```

然后打开 `public/data/report.json`，找到 `checkout-api` 的三个异常信号。

## 四、必须亲自完成的修改练习

1. 把错误率阈值从 5% 改为 8%，重新运行测试和分析。
2. 修改生成器中的异常开始时间，观察时间图表如何变化。
3. 增加一个新的错误码并确认重复错误规则是否触发。
4. 为任意新规则补充一个 pytest 测试。
5. 在 Runbook 中增加一条你能够解释的排查建议。

完成这些练习后，你才能真正把项目视为自己的工程经历。

## 五、目前没有实现的内容

项目尚未使用机器学习模型、数据库、Kubernetes、真实云平台和 OpenTelemetry。面试时必须明确说明这是一个基于统计基线和规则智能的原型，不要称为生产系统。
